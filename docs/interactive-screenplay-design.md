# 互动影游：有限分支与状态保留的生成设计

## 改造前样本结论

改造前使用同一版本真实模型生成了两份完整样本，均通过结构生成和 PRD 解析，但均不能据此判定为高质量剧本。

- 民俗《夜不呼名》：server/scratch/branch-source-1795400689728-16124，39 节点、19 剧情片段、20 结局。n1_2_1_2_2 正文先写陈默捡起并带走裂铃，随后又写三叔公将同一枚裂铃寄给他，缺少归还交接；其他路线分别采用超自然活尸和集体癔症/谋杀解释，世界真相未固定。
- 科幻《轨道坠落》：server/scratch/branch-source-1795400689728-16208，35 节点、17 剧情片段、18 结局。n1_2_1_1 确认破坏者是前员工赵启明，n1_2_2_1_2 却确认是站长为掩盖贪污制造事故；同一结局里周野兄妹已离开，林岚随后隐藏的芯片又出现在周野手中，缺少回返与取得过程。n1_1_2_1_2 中林岚在未修好逃生舱时留下传证据，周野兄妹却直接使用逃生舱撤离，缺少修复交代。

这说明单纯禁止合流会导致结局膨胀，且路径隔离不等于固定世界事实或保证同路径因果完整。

   https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md

## 默认生成结构（已实现；内容验收未通过）

### 1. 先确立唯一故事事实

先生成独立于玩家路线的 story bible：真实事件、幕后原因、角色动机与秘密、时间线、关键物品的初始归属、物理/超自然规则。区分客观事实、角色误解和待揭示信息。玩家可以改变事件结果与获知程度，不能仅因选择不同而改变早已发生的事故原因。

### 2. 先设计有限结局及其条件

默认 2–3 个结局；这是针对短篇影游的产品预算建议，不是资料声称的行业标准。结局先说明主题回答、人物命运、必要事实与达成条件。只在创作者明确要求时增加。

同一结局必须具有一致的可见事实；不能把“妹妹生还团聚”和“妹妹死亡、公开证据”称为同一段可复用结局画面。优先把真正改变人物命运的决定集中到后段，减少前期状态组合。

### 3. 以共同关键事件为主干，局部分支有后果

建议短篇默认 3 幕、3–5 个重要选择点，每点通常 2 个选项、1–2 个短后果片段。分支结束回到事先规划的共同事件，合流点的场景事实必须来自每条入路都能保证的内容。

分支前先定义下一共同事件的场景契约：谁在场、在哪里、何时、共享必需道具和共同已知信息。再倒推每个选项怎样自然走到这个事件；不把两条写完的任意剧情事后硬接起来。

### 4. 用少量明确状态保留选择影响

只记录真正影响后续的状态，例如 evidence_acquired、ally_trust、alarm_raised。是否持有证据等离散事实用布尔/枚举，不能以无关数值积分替代因果。每个重要选择规划：即时后果、状态变化、以后在哪个节点兑现。避免只有文案不同、后续毫无影响的假选择。

现有 UniversalPrdSpec 已有 initialState、outcomes.stateChange、wiring.condition。需要核对播放器实际条件语法和执行顺序后再接通完整链路，不能仅在提示词里宣称支持。

### 5. 扩写按场景职责提供上下文

保留逐节点扩写，但不再把某条完整历史当作合流后的共同经历：
- 共享场景：世界事实、共同入场契约、当前可说的共同信息。
- 分支场景：世界事实、选定行动、该路径状态和直接后果。
- 状态回响：只在需要时生成短的明确视频变体，再连接共同场景。

文字中的条件逻辑必须编译为实际条件连接与明确片段；不能向分镜交付“阿萤若失踪则缺席”“A 或 B 说”等占位文本。

### 6. 控制作者工作量而非事后截断

生成契约中明确结局数量、选择点数量和局部分支长度；超出预算应在规划阶段重新设计节奏，不截掉已生成的支线，不把 20 个终局只换成 3 个名字。

## 对现有代码的调整方向

- 用故事事实、有限结局、章节共同事件与局部分支规划替代 branch-tree.ts 的默认完全展开。
- 继续保留代码装配节点/连接与确定性 PRD 转换，避免再次让模型猜接线。
- 为状态变化和条件连接建立单一契约，贯穿生成、存储、PRD、播放器。
- 将 expand-paths.ts 的“每节点唯一祖先历史”改为根据场景职责供给共同事实或分支状态；不能再通过禁止一切合流达到一致性。
- 原有结构验证作为必要边界保留，但核心质量来自上述源头规划，不以额外审查代替设计。

本文件是查阅资料后的具体设计方案，当前生产生成器仍是上一版剧情树，尚未实施上述状态合流架构。

## 本轮实现边界

- 默认依次生成 story bible、固定选择行动与共用场景/汇合、局部分支与终局分配；默认 3 个重要选择，每次 2 个选项；前段每条选择有短后果并汇合，最后一次选择直接按状态进入 2–3 个终局，禁止终局分歧后再强制合流。2 幕仍包含 3 次选择，4–6 幕按幕数配置选择数。暂不生成中途状态回响变体；状态差异由短后果与终局呈现。
- 状态记录选择行动，每个选择只写入一次（第一项 true、第二项 false）。两个行动由共用节拍规划确定，文案与状态由代码绑定；不让模型把“是否进入实验舱”设成 false 后又写出已经进入。物品当前归属仍由具体场景事实表达，不把行动历史误当作物品永久状态。代码枚举全部状态组合（默认 8 种），Schema 为每种组合要求一个既有结局 ID，模型不再自行书写易漏项的布尔表达式。代码据此编译条件边，不是给生成完的树剪枝。条件为 JSON 对象：组内键值相等合取，多条边必须唯一命中；禁止 eval。
- v3 Markdown 的 makemv-state 注释保存 initialState、选项状态变化与故事圣经，条件后继或条件选项保存在对应节点。复用现有 screenplay 字符串资产持久化，不引入第二份路由源；PRD 仍确定性装配。
- 实际总装此前既未消费 wiring，也未处理普通片段 next。本轮从 PRD 构建播放场景、选择、终局与条件路由，媒体输入仅补正文/素材。旧输入无 wiring 时仍使用 script 播放表。
- 保留 legacy branch-tree 编译器用于旧格式测试，不再用于新剧本默认生成。
- 结构校验只检查可达、条件完备/唯一等协议；不会宣称它能证明角色行为与道具传递语义正确。
## 模型调用适配修复

真实检查发现当前 Mastra 的 agent.model 为空，模型由 agent.llm.getModel() 持有。generateStructured 原先只读前者，导致工序指定的模型被全局模型替代。本轮补齐真实模型入口，并为大纲规划启用独立的推理模型变体；默认模型与全局配置不变。当前 SiliconFlow 请求显式发送 enable_thinking=true；其他不支持该私有字段的网关不发送它。

回归测试用实际 Agent 对象和截获的 HTTP 请求验证：大纲请求 true、默认请求 false、结构化适配层仍保持大纲模型。服务端编译、分支契约测试（含 8 条实际播放器路径和总装落盘）、Agent 运行时测试已通过。旧 task-tools-assembly.test.ts 的 mock 返回 GDD 而非技术规划，未通过；未将它计入通过结果。

最终两份样本及具体缺陷见 [本轮验收记录](interactive-screenplay-validation.md)。结构通过不代表内容通过；本轮不能宣称高质量目标已完成。

## 2026-11-23：用事实账本替代自由汇合事实

默认入口改为 `causal-planner.ts`，旧 bottleneck 编译器仅保留兼容测试。先生成不可变设定及可变事实字典，再逐幕根据计算出的共有事实生成行动。每个行动声明 requires/effects；未变更事实继承，变更必须有已知原值。各路线的世界状态独立保留，下一幕上下文取交集，不再让模型填写合流事实。

最后对实际可达终态生成 2–3 个结局前提。代码检查唯一覆盖与可达性，为每个结局求入场事实交集，并编译成现有布尔历史路由。最后抉择仍有独立后果片段，不设强行合流。大纲最多对当前无效方案修订一次，失败则明确报错，不进入扩写。

扩写不再接收过时的 initialFacts，并携带 before/after、声明变化和不可用事实。该方案保证已登记事实的传播与路由，不能机械证明自然语言完整登记了事实，也不能保证对白和戏剧质量。真实样本验收必须单独记录。

共有场景与局部后果现分为两次生成：先算 common 的出场事实，再构建分支 schema。requires 的值被约束为当时真实值；effects 的可用键只包含当时共有的事实，取值来自注册字典。变更的原值由代码补入节点契约，不要求模型重复填写。默认三次选择为八次规划请求（设定一次、每个节拍两次、结局一次），不是旧流程的三次请求。

## 继续修订：代码绑定前提、计算结局分区

- 模型行动输出移除 requires，只保留 summary/effects；代码从当前入路交集绑定 requires。模型不再重复输出前提值，避免把将要发生的变化填入前提字段。
- 结局生成不再返回自由填写的前提条件或状态分配表。模型从实际存在分歧的事实中选取一个核心矛盾，代码按真实取值建立分区。2–3 种值各自成组；更多取值最多前三组，其中第三组汇集剩余路线且仅使用其事实交集。每条路线恰好归属一个组。
- 分组完成后分别生成结局，输入是各组的共有入场事实。既有布尔路由协议和最多三个结局的边界不变。
- 该结构消除了模型填写前提值、遗漏/重叠分配路线的职责；自然语言未登记动作与戏剧质量仍需要真实样本验证，不能把结构计算当作全文语义证明。

### 状态先行的默认规划入口

进一步删除了局部分支自由摘要：代码枚举当前共有且 scope 为 branch 的事实转变，模型只选择转变编号与短行动标签。A 应用转变、B 保持原状态，代码生成节点事实账本；共有场景也先生成 effects，后续扩写根据 before/after 写正文。shared 类型的位置、在场角色及公共时间不交给局部分支修改。内部事实 key 统一由代码分配，模型只提供事实含义和值域。

为了避免初始设定污染后续场景，规划和扩写使用 causalBackground（仅开场之前的原因及恒定规则）、角色身份与当前事实，不再反复携带包括当前生死/道具/秘密的完整圣经。旧圣经仍保存在产物用于兼容。每次选择均有登记差异，但并不要求每次选择都增加独立结局。

终局输出现区分决定性行动、最终命运、核心事件结果、最后画面；局部工序不再带“完整输出全剧大纲”的旧指令。文本模型的空响应只在剧本工序显式开启时重试当前调用一次，语义或字段错误不重试。最终内容验证及残留问题见 interactive-screenplay-validation.md；结构完成不能代替全文因果与戏剧质量验收。

## 2026-11-23：行动组合、短承接与复合终局（当前入口）

本节描述当前实现，前面的单状态选项/单轴结局属于已替换的实验过程。

- 先生成固定设定及有限事实，再生成共同事件骨架和 2–3 个结局方向。结局条件是多事实合取/析取，按明确优先级匹配，剩余路线进入兜底方向。代码核对每个方向实际可达，不再按单个变量机械分组。
- 两个选项都声明行动、收益、代价与后续回报；可同时改变多个事实。模型不填写当前前提值，而是列出所使用的事实编号，代码从真实世界绑定。
- 选择后先生成即时后果，必要时增加一个短承接节点，明确脱困、移动或交接。编译器核对路线真正到达下个共同事件要求的事实，不能把“有一个后继链接”当成“人物已经会合”。
- 先前选择形成不同世界时，代码按真实入场世界编号生成局部后果变体。同一选项文案可因已有证据/伤势不同产生不同后果；模型不能自由分配历史。变体经过条件选项进入，沿用现有 Markdown、PRD 和播放器协议。
- 共有场景仅使用入路事实交集；短承接能读取自己唯一的前序分支正文。事实未改变时保留，不以合流名义清零。所有重要选择的全部结果都被抹平时直接报错。

本架构仍不构成自然语言因果证明。状态值域、动作摘要、关键设施及最终命运仍需内容验收；短变体也会增加视频制作片段量，最多三个结局不等于最多三个分支片段。


### 续作：汇合锚点与收束片段的职责

实际验证发现两个不同的问题：一是同一“未公开”方向包含没有原件、持有原件但没有传输两种结果，不能共用具体的收束画面；二是模型会把已取证、已信任等成果塞进下一幕入场条件，迫使两项选择归于相同状态。

当前实现将事实 scope 分为 shared（空间、在场、行动自由等必要承接）和 branch（证据、伤势、关系、资源、知识和目标进度）。骨架的 entryBeforeScene/finalEntry 使用只含 shared 字段的动态 Schema，条件终局仍可读取完整事实。共同动作的 uses/effects 也只暴露真实共有事实。分类由本故事设定生成，不包含固定人物、道具或预制结果。分类正确性仍需要真实内容审阅，不能仅凭 scope 字段保证语义正确。

同一方向下的真实终态分别生成 ending_i_resolution_vN 收束场景，再接 ending_i 共用结局字幕；实际终局仍为 2–3 个。字幕由代码生成，收束正文继续由模型创作。每个节点携带所有真实入路共有的 establishedEvents，后续大纲及正文均接收实际动作记录，保留伤势部位、物品保存方式和已完成转移。唯一直接前场也传给收束片段；汇合场景不选择任意支线正文。


### 续作：结局创作目标与实际终态

上述“预设条件不可达则报错”的策略在完整科幻样本上仍失败：模型先猜出燃料、门锁、信任度的精确组合，却没有在后续行动中兑现。增加提示词不能使一个虚构的可达性条件变为真实结果。当前入口因此将骨架阶段的结局保留为创作目标，不让模型提前填写 whenAny 条件。全部行动大纲完成后，代码先枚举真实终态，模型只能对这些编号归纳 2–3 个实际可兑现的结局大纲，解释多项事实与代价。编号分配必须完整且互斥；代码再从该组的真实选择历史生成路由，不由模型写布尔接线。这个步骤仍属于大纲规划，发生在任何正文扩写之前，不是正文完成后的修补或删改。未实现的早期目标不允许通过新增道具、救援或死亡补足。

此外，行动组合使用联合 Schema：若没有短承接，后果本身必须明确到达下一幕；若有承接，最后的 effects 必须包含目标位置/自由条件的字面值。既有已发生动作继续传入后续规划与扩写；objectiveTruth 随固定规则传入，避免从种子到后续工序时丢失不可变真相。


### DeepSeek Flash 单用例：先确定骨架，再补足事实表达能力

科幻样本第一幕将同一高能电池分配给不同用途，但种子事实只有满电/耗尽，无法表达实际分配差异。两项后果最终都成了相同满电状态，大纲因此正确拒绝继续。当前在戏剧骨架之后、任何行动生成之前增加事实补全：只能给已有 branch 事实增加必要值，或添加少量独立 branch 事实；编号由代码分配，旧编号、初始值、已有值及 shared 汇合维度保持原样。补全依据整个骨架的实际收益与代价，禁止加入纯粹表示选了 A/B 的伪事实。随后用补全后的字典生成动作、传播状态与扩写。它是大纲前置建模步骤，不是正文出错后的改写。


### 正文工序只生成文字

正文节点只有一个 narrativeText 字符串，仍要求模型返回 JSON 容器没有提供额外结构信息，却在 Flash 真样本中发生直接返回剧本正文而解析失败。当前 write-node.ts 使用 AI SDK generateText 生成场景文字，代码负责包装内部字段；大纲仍用结构化生成，节点、状态、选项、接线、结局字幕仍由代码根据大纲确定。只对真正空正文保留一次重试；API 错误直接传播，不解析或猜补剧本 JSON。既有各节点扩写边界及 PRD 确定性转换保持有效。


### 篇幅控制：先压缩结构，再扩写

默认短篇以单路线约1200–1800字为目标，保留按幕数安排的重要选择和2–3个结局。骨架每幕增加 decisionPurpose，声明本次选择独有的戏剧作用与新增信息；行动规划同时接收已完成选择，避免反复讨论同一个取舍。

compileBundle 的 combineLanding 模式先按原顺序传播并验证后果与承接，再将二者合成为同一场景：合成外部前提排除由前一动作建立的中间条件，最终状态取顺序执行结果，摘要保留完整动作。受困、脱困、物品转移仍有大纲依据，不为普通转场另生成一个播放片段。旧的单独承接编译模式仍可用于既有调用与回归。

扩写提示按共用场160–200字、后果场180–230字、收束场220–280字分配篇幅，仅减少重复解释、争执和气氛描写，不在生成后截断正文。成稿节点标题使用幕名、选项名或结局名，不再重复输出整段大纲摘要；完整大纲留在 premise。事实差异仍保留在状态中，不能为了缩减节点而把互斥历史硬并成同一画面。


## 可读剧本输出（v4）

全景剧本按幕排列共同正文和 A/B 分支，同一选项的前情变体相邻展示，以“第几幕选 A/B”标注适用条件；段尾显示明确去向，收束与结局集中在最后。阅读标签从实际路由生成，不合并或删除分支状态。v4 在 HTML 注释中保留节点、条件、选项与状态契约，正文在 makemv-node 与 makemv-flow 之间，PRD 解析直接消费契约。v2/v3 旧稿仍可解析。前端阅读模式隐藏注释，显示标题层次并支持段内跳转；编辑模式保留完整源文。
