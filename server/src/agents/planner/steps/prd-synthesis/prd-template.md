# PRD 母表（通用）

给生成 PRD 的 AI：下面这张表只固定**策划案由哪几块组成**，以及**每一块是什么内容**。块里怎么分小节、用不用列表或表格、写多少字、一个互动点展开几段，全都你自己决定。装不下的内容自己加块。

| # | 模块 | 这一块是什么内容 | 不要塞进来的东西 |
| --- | --- | --- | --- |
| 1 | 互动点 | **只写互动游戏玩法**：玩家怎么操作、玩法规则、什么算完成、给什么反馈。选择类只写玩法本身（几个选项、怎么选、能否反悔、超时怎么判）；复杂玩法（多步找证据、限时、连续操作、找不齐会怎样）都在这里展开 | 播完去哪、按钮上写什么字（那是第 2 块）；剧情正文、UI 尺寸、状态矩阵、验收条款 |
| 2 | 播放流程 | 从哪段开始、正常顺播到哪结束；哪几段播完会走不同的路、每条路按钮上显示什么字、各条路分别接哪些编号、在哪一段重新汇合；最后怎么收尾。写完这一块，读者不用翻别处就能排出整部片子的播放顺序 | 玩法细节（那是第 1 块）；不再单列一遍视频台账 |
| 3 | 页面 | 除播放页之外还需要哪些页面，**主页必须有**；每页从哪进、能去哪、展示哪些编号；进度怎么解锁、「继续」记到什么粒度、播放中怎么退出 | 视觉稿、实现代码 |

## 扩展

- 上面 3 块是最小集，缺一不可；块内结构、标题层级、体裁自己定。不要另起「通用规则 / 其他 / 补充说明」这类兜底块。
- 遇到 3 块装不下的内容——特殊结局、额外外壳页、周目、复杂玩法自成体系、素材规格等——**加一个新模块**，写清模块名和它负责什么，别硬塞进不相关的块，也别在好几块里各写一点。
- 新模块同样遵守下面的边界。

## 边界（只有这四条）

- 剧情正文只在 `story.md`（编号 + 正文），本表不复述；唯一例外是按钮上显示的选项文字。
- 编号 = 视频文件名 = `story.md` 段落号，全篇同形；任何去向只能写已存在的编号，不新造。
- 一律叫**互动点**。互动可以是一次选择，也可以只是找线索、做一个手势，多数不改变走向；不要把它窄化成「分支」或「抉择点」。
- 每块只写自己那一块的事，不在别块重复。
